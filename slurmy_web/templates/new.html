Run and build your provers

Build the provers

Solver directories are packaged automatically. If a prover needs compiling, add its root and recipe below. Build once per root, even if several configurations use it. Builds run on compute nodes; downloaded outputs replace matching files in the local root.

Import build settings from a file

This file supplies both prover and limiter resources and their build recipes.

Choose the problems

Every configuration runs on every file in the union of all globs. Duplicate problem paths are removed.

The selected jobpairs.csv already specifies the problem for each call. No additional problem selection is needed.

Run and build the resource limiter

Wrap each prover call with a limiter. Runsolver output options save the solver output, watcher log, and measurements for inspection.

Available placeholders and runsolver output capture

{% raw %}{{problem}}, {{wc_limit}}, {{cpu_limit}}, {{mem_limit}}, {{mem_limit_mib}}, {{cores}}, {{cpus}}, {{solver_command}}, {{watcher_log}}, {{var_file}}, {{solver_log}}, {{controller_log}}{% endraw %}

Leave path and command placeholders unquoted; Slurmy quotes them. mem_limit is decimal MB; mem_limit_mib is MiB.

{% raw %}/path/to/runsolver --cpu-limit {{cpu_limit}} --wall-clock-limit {{wc_limit}} --rss-swap-limit {{mem_limit_mib}} --watcher-data {{watcher_log}} --var {{var_file}} --solver-data {{solver_log}} {{solver_command}}{% endraw %}

Build the limiter

Choose the directory containing the executable, or where the remote build will produce it. Select no build if it is ready to run on the cluster. If this root is already listed under Provers, declare it only once.

The building.txt selected under Provers supplies the limiter’s root and build recipe too.

Review before saving
