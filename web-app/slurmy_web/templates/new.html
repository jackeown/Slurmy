Choose the problems

Every configuration runs on every problem in the union of the selected paths, globs, and ZIP/tar archives. Duplicate problem paths are removed. Archives contribute their .p and .tptp files.

Custom files replace the cluster set. Slurmy collects them under a job-local Axioms/ directory, preserving paths below any existing Axioms/. Include nested dependencies.

Limiter configuration

Available limiter placeholders

Each value belongs to one solver call. Expand a placeholder below for its meaning and how to use it.

{% raw %}{{solver_command}}{% endraw %}

Runs the generated solver wrapper for this call. This placeholder is required in the limiter invocation so the limiter actually starts the solver and Slurmy can capture its stderr separately. Put it after the limiter's own options, typically at the end of the command, and use it only once. Leave it unquoted; Slurmy inserts the shell-safe wrapper invocation.

{% raw %}{{wc_limit}}{% endraw %}

The call's wall-clock limit in seconds: elapsed real time, including time spent waiting or using multiple cores. With runsolver, pass it to --wall-clock-limit. This comes from the call's jobpair settings; it is not the time limit for an entire Slurm batch.

{% raw %}{{cpu_limit}}{% endraw %}

The call's CPU-time limit in seconds, summed across its processes and cores. A parallel solver can spend CPU time faster than wall-clock time. With runsolver, pass it to --cpu-limit.

{% raw %}{{mem_limit}}{% endraw %}

The call's memory limit converted from bytes to decimal megabytes (1 MB = 1,000,000 bytes), rounded up. Use this only if your limiter expects decimal MB; runsolver's --rss-swap-limit expects MiB instead.

{% raw %}{{mem_limit_mib}}{% endraw %}

The same memory limit in mebibytes (1 MiB = 1,048,576 bytes), rounded up. Use this for runsolver's --rss-swap-limit. Choose one memory placeholder to match the units required by your limiter.

{% raw %}{{cores}}{% endraw %}

The number of physical cores available to this solver call. This is a per-call allocation, not the number of concurrent calls in a Slurm batch. Pass it only if your limiter needs an explicit core count; Slurmy handles the Slurm core allocation separately.

{% raw %}{{watcher_log}}{% endraw %}

A file for runsolver's human-readable watcher information: what it observed while supervising the call, especially limit or termination events. Pass it with --watcher-data {% raw %}{{watcher_log}}{% endraw %}. This is not the solver's output or Slurmy's controller log. The file may be empty for an uneventful call; if you omit the flag, it will not be captured. Leave the placeholder unquoted.

{% raw %}{{var_file}}{% endraw %}

A file for runsolver's structured NAME=VALUE measurements, such as elapsed/CPU time and memory use. Pass it with --var {% raw %}{{var_file}}{% endraw %}; Slurmy reads these values to report usage and interpret limits. Unlike the watcher log, this file is meant to be machine-readable. Leave the placeholder unquoted.

{% raw %}{{solver_log}}{% endraw %}

A file for the solver's standard output: proof status, answers, or text the solver prints. Pass it with --solver-data {% raw %}{{solver_log}}{% endraw %}. Slurmy's solver wrapper separately captures stderr, so the jobpair viewer can show the two streams apart. An empty file can be normal if the solver prints nothing. Leave the placeholder unquoted.

{% raw %}{{problem}}{% endraw %}

The packaged problem's path on the cluster. Normally the solver command already contains it, so the limiter does not need this placeholder. Use it only if your limiter has a separate problem-path option. Leave it unquoted; Slurmy inserts the quoted path.

Use only placeholders and options your limiter supports. Slurmy captures its own controller diagnostics automatically; that log is not a limiter parameter.
