Placeholders for this invocation

Each value belongs to one solver-problem pair. Expand a placeholder below for its meaning and how to use it.

{% raw %}{{solver_command}}{% endraw %}

Runs the generated solver wrapper for this call. This placeholder is required in the limiter invocation so the limiter actually starts the solver and Slurmy can capture its stderr separately. Put it after the limiter's own options, typically at the end of the command, and use it only once. Leave it unquoted; Slurmy inserts the shell-safe wrapper invocation.

{% raw %}{{wc_limit}}{% endraw %}

The solver-problem pair's wall-clock limit in seconds: elapsed real time, including time spent waiting or using multiple cores. With runsolver, pass it to --wall-clock-limit. This comes from the solver-problem pair's solver-problem pair settings; it is not the time limit for an entire SLURM batch.

{% raw %}{{cpu_limit}}{% endraw %}

The solver-problem pair's CPU-time limit in seconds, summed across its processes and cores. A parallel solver can spend CPU time faster than wall-clock time. With runsolver, pass it to --cpu-limit.

{% raw %}{{mem_limit}}{% endraw %}

The solver-problem pair's memory limit converted from bytes to decimal megabytes (1 MB = 1,000,000 bytes), rounded up. Use this only if your limiter expects decimal MB; runsolver's --rss-swap-limit expects MiB instead.

{% raw %}{{mem_limit_mib}}{% endraw %}

The same memory limit in mebibytes (1 MiB = 1,048,576 bytes), rounded up. Use this for runsolver's --rss-swap-limit. Choose one memory placeholder to match the units required by your limiter.

{% raw %}{{cores}}{% endraw %}

The number of physical cores available to this solver-problem pair. This is a per-solver-problem pair allocation, not the number of concurrent solver-problem pairs in a SLURM batch. Pass it only if your limiter needs an explicit core count; Slurmy handles the SLURM core allocation separately.

{% raw %}{{watcher_log}}{% endraw %}

A file for runsolver's human-readable watcher information: what it observed while supervising the solver-problem pair, especially limit or termination events. Pass it with --watcher-data {% raw %}{{watcher_log}}{% endraw %}. This is not the solver's output or Slurmy's controller log. The file may be empty for an uneventful solver-problem pair; if you omit the flag, it will not be captured. Leave the placeholder unquoted.

{% raw %}{{var_file}}{% endraw %}

A file for runsolver's structured NAME=VALUE measurements, such as elapsed/CPU time and memory use. Pass it with --var {% raw %}{{var_file}}{% endraw %}; Slurmy reads these values to report usage and interpret limits. Unlike the watcher log, this file is meant to be machine-readable. Leave the placeholder unquoted.

{% raw %}{{solver_log}}{% endraw %}

A file for the solver's standard output: proof status, answers, or text the solver prints. Pass it with --solver-data {% raw %}{{solver_log}}{% endraw %}. Slurmy's solver wrapper separately captures stderr, so the solver-problem pair viewer can show the two streams apart. An empty file can be normal if the solver prints nothing. Leave the placeholder unquoted.

{% raw %}{{problem}}{% endraw %}

The packaged problem's path on the cluster. Normally the solver command already contains it, so the limiter does not need this placeholder. Use it only if your limiter has a separate problem-path option. Leave it unquoted; Slurmy inserts the quoted path.

Use only placeholders and options your limiter supports. Slurmy captures its own controller diagnostics automatically; that log is not a limiter parameter.
